# Manual request template

Write **one** staff-facing markdown file per run: `runs/<slug>/manual-requests.md`.

Audience: company staff who will fetch, scan, sign, or confirm documents. Not an AI scratchpad.

## Required shape

```markdown
# Manual document requests — <Project / Buyer>

**Bid:** <short name + bid number if any>
**Needed by:** <date>
**Context (2–5 sentences):** what we are bidding, what category of work evidence must fit, any stretch guidance.

## Requests

| # | Document | Group | Class | Why needed | Stretch / notes | Owner | Status |
|---|---|---|---|---|---|---|---|
| 1 | … | G3 Company docs | library | Part 1 upload | Face-check directors on cert | Legal | Have / Need |

## Evidence of work (if any)

For each requested proof: state the **work category** we need it to support (e.g. B2B CRM / work-tracking for government officers). Note that library proofs may use **open but honest** scope framing on the cover — staff should not alter signed contracts.

## Signatures / wet ink

List forms that need print + sign after drafts exist.

## Not needed (explicit)

Items staff might assume — call out N/A so they do not chase them.
```

## Rules

- One file, directly sendable (email/chat paste).
- Include enough context that “evidence of work” requests are **stretchable into this bid’s category** without lying.
- Separate **Have in library (copy + face-check)** from **Need new**.
- Do not put internal scoring strategy or AI process language in this file.
- Update Status as items arrive; pack CHECKLIST remains the upload tracker.
