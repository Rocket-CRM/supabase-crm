28 June incident summary

  1. Methodology
    API capacity is protected two ways: autoscaling with traffic, and pre-provisioning higher minimum servers when a large campaign is planned with us.
  2. What happened
    A client ran a surprise nationwide campaign — hundreds of thousands of registrations and coupon claims in a short window — without prior notice.
  3. Why it failed
    No pre-provisioning was in place. Usually that alone is fine — the system can still autoscale. In this case the surge volume exceeded our AWS maximum allocated server capacity, so scaling could not go beyond that hard limit until AWS raised it.
  4. What we did
    Urgently increased the AWS capacity ceiling, and optimized the coupon-claim path that was compute-heavy under extreme load.
  5. Why not again
    Maximum allocated capacity is now ~5× higher, and the claim path is optimized — a surprise surge of that scale should no longer require an emergency limit increase.
