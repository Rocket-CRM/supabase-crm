# คู่มือตั้งค่า Spin Wheel สำหรับ Customer Success

> เอกสารนี้อธิบายแนวคิดและความหมายของแต่ละการตั้งค่าใน Admin — สำหรับทีม CS ใช้ onboard ลูกค้า, ตอบคำถาม, และช่วย troubleshoot  
> อ้างอิงจาก `requirements/Spin_Wheel.md` (สเปกเชิงเทคนิค)

---

## 1. Spin Wheel คืออะไร

Spin Wheel (วงล้อเสี่ยงโชค) คือแคมเปญเกมมิฟิเคชันใน Loyalty ที่ให้สมาชิก **หมุนวงล้อเพื่อลุ้นรางวัล** ระบบจะสุ่มช่องรางวัล (segment) ตาม **น้ำหนักความน่าจะเป็น (weight)** แล้วมอบรางวัลจริงให้สมาชิกโดยอัตโนมัติ

**หนึ่งครั้งที่หมุน = หักค่าใช้จ่าย (ถ้ามี) + สุ่มช่องหนึ่งช่อง + มอบรางวัลทั้งหมดในช่องนั้น**

ลูกค้า (merchant) ตั้งค่าได้ว่า:
- ใครหมุนได้บ้าง (tier, persona, tag, เดือนเกิด)
- หมุนราคาเท่าไร (แต้มฟรี / แต้ม / ticket)
- หมุนได้กี่ครั้งต่อวัน/สัปดาห์/เดือน
- วงล้อมีช่องอะไรบ้าง โอกาสเท่าไร และรางวัลแต่ละช่องคืออะไร

## 2. แนวคิดสำคัญ (อ่านก่อนตั้งค่า)

| คำศัพท์ | ความหมาย | ตัวอย่าง |
|---|---|---|
| **แคมเปญ / วงล้อ** | กล่องการตั้งค่าหลัก — ชื่อ, ช่วงเวลา, ค่าใช้จ่าย, เงื่อนไขสิทธิ์ | "Summer Lucky Wheel" |
| **ช่อง / Segment** | หนึ่งช่องบนวงล้อ — มีชื่อ, น้ำหนักโอกาส, อาจจำกัดจำนวนรางวัล | "10 แต้ม", "ลองใหม่" |
| **Outcome (รางวัลจริง)** | สิ่งที่สมาชิกได้รับเมื่อชนะช่องนั้น — หนึ่งช่องอาจมีหลาย outcome | ช่องเดียว = 10 แต้ม + คูปอง 1 ใบ |
| **การหมุน (Spin)** | บันทึกหนึ่งครั้งที่สมาชิกกดหมุน — ใช้นับ limit และ audit | สมาชิก A หมุน 09:00 น. ได้ 10 แต้ม |

> **สำคัญ:** ชื่อช่อง (`label`) เป็นข้อความโชว์บนวงล้อ — **ไม่ใช่**สิ่งที่ระบบมอบให้ รางวัลจริงอยู่ที่ **Outcome** เท่านั้น

## 3. การตั้งค่าแคมเปญ (Campaign)

### 3.1 ข้อมูลพื้นฐาน

| การตั้งค่า | ความหมาย | ค่าว่าง / ค่าเริ่มต้น | หมายเหตุสำหรับ CS |
|---|---|---|---|
| **ชื่อ (name)** | ชื่อแคมเปญที่แสดงใน Admin และแอปสมาชิก | บังคับกรอก | ใช้ชื่อที่สมาชิกเข้าใจ เช่น "วงล้อสงกรานต์ 2026" |
| **คำอธิบาย (description)** | รายละเอียดเพิ่มเติม | ไม่บังคับ | ใส่กติกาโปรโมชันสั้น ๆ ได้ |
| **เปิดใช้งาน (active_status)** | เปิด/ปิดแคมเปญ | เปิด (true) | ปิดแล้วสมาชิกหมุนไม่ได้ |
| **วันเริ่ม (window_start)** | เริ่มให้หมุนได้ตั้งแต่เมื่อไร | ว่าง = ไม่จำกัดวันเริ่ม | ตั้ง timezone ให้ตรงกับโปรโมชัน |
| **วันสิ้นสุด (window_end)** | หมุนได้ถึงเมื่อไร | ว่าง = ไม่จำกัดวันสิ้นสุด | หลังหมดเวลา สมาชิกเห็นแคมเปญไม่ active |

### 3.2 ค่าใช้จ่ายในการหมุน

| การตั้งค่า | ความหมาย | ตัวอย่าง |
|---|---|---|
| **cost_currency** | สกุลที่ใช้จ่าย | `points` (แต้ม) หรือ `ticket` (ตั๋ว/โทเคน) |
| **cost_amount** | จำนวนที่หักต่อ 1 ครั้ง | `0` = หมุนฟรี, `100` = หัก 100 แต้ม |
| **cost_ticket_type_id** | ประเภทตั๋ว (เมื่อจ่ายด้วย ticket) | ต้องเลือก ticket type ที่ active |

**สรุปสำหรับ CS:**

| ตั้งค่า | พฤติกรรม |
|---|---|
| แต้ม + amount = 0 | หมุนฟรี ไม่หัก wallet |
| แต้ม + amount > 0 | หักแต้มก่อนสุ่มรางวัล |
| ticket + amount > 0 | หักตั๋วตามประเภที่เลือก |

รางวัลที่ได้ **ไม่จำเป็นต้อง** เป็นสกุลเดียวกับค่าใช้จ่าย — หมุนด้วยแต้ม แต่ชนะ ticket ได้

### 3.3 เงื่อนไขสิทธิ์ (Eligibility)

กำหนดว่า **ใครหมุนได้** — เงื่อนไขทุกข้อที่ตั้งไว้ต้อง **ผ่านทั้งหมด (AND)**

| การตั้งค่า | ความหมาย | ว่าง / ไม่เลือก = |
|---|---|---|
| **allowed_tier** | Tier ที่หมุนได้ | ทุก tier |
| **allowed_persona** | Persona ที่หมุนได้ | ทุก persona |
| **allowed_tags** | Tag ที่สมาชิกต้องมีอย่างน้อย 1 อัน | ไม่เช็ค tag |
| **allowed_birthmonth** | เดือนเกิด (1–12) ที่หมุนได้ | ทุกเดือน |

**ตัวอย่าง:** ตั้ง `allowed_birthmonth = [6]` → เฉพาะสมาชิกที่เกิดเดือนมิถุนายนหมุนได้

**ข้อจำกัด:** ไม่รองรับ buyer/seller type แบบ reward — ใช้ tier/persona/tag แทน

### 3.4 จำกัดจำนวนครั้ง (Participation Limits)

ควบคุมว่าหมุนได้กี่ครั้ง — นับจาก **ทุกครั้งที่กดหมุน** รวมช่อง "ไม่ได้รางวัล" ด้วย

| ฟิลด์ | ความหมาย | ตัวเลือก |
|---|---|---|
| **scope** | นับแบบไหน | `user` = ต่อคน, `total` = ทั้งแคมเปญรวม |
| **count** | จำนวนครั้งสูงสุด | เช่น 3 |
| **time_unit** | ช่วงเวลา | `day`, `week`, `month`, `year`, `all_time` |

**ตัวอย่างที่ลูกค้ามักขอ:**

| ความต้องการ | scope | count | time_unit |
|---|---|---|---|
| หมุนได้ 3 ครั้ง/วัน/คน | user | 3 | day |
| หมุนได้ 1 ครั้ง/สัปดาห์/คน | user | 1 | week |
| แคมเปญมี spin รวม 1,000 ครั้ง | total | 1000 | all_time |

สมาชิกเห็น `spins_remaining` (ครั้งที่เหลือ) และ `next_reset_at` (เวลารีเซ็ต limit รายวัน/สัปดาห์/เดือน) บนหน้าวงล้อ

## 4. การตั้งค่าช่องวงล้อ (Segment)

แต่ละช่อง = หนึ่งสไลซ์บนวงล้อ

| การตั้งค่า | ความหมาย | หมายเหตุ |
|---|---|---|
| **label** | ข้อความบนช่อง | เช่น "50 แต้ม", "ลองใหม่อีกครั้ง" |
| **weight** | น้ำหนักความน่าจะเป็น (relative) | ยิ่งมาก ยิ่งมีโอกาสชนะ — **ไม่จำเป็นต้องรวม 100** |
| **display_order** | ลำดับแสดงบนวงล้อ | 0, 1, 2, … |
| **active_status** | เปิด/ปิดช่อง | ปิดแล้วไม่ถูกสุ่ม |
| **is_no_win** | ช่อง "ไม่ได้รางวัล" | true = ไม่มี outcome, ไม่มอบอะไร แต่ยังหักค่าหมุน (ถ้ามี) |
| **stock_total** | จำนวนรางวัลช่องนี้ทั้งหมด | ว่าง = ไม่จำกัด |
| **stock_remaining** | จำนวนที่เหลือ | เหลือ 0 → ช่องนี้หลุดจากการสุ่ม |

### 4.1 เรื่องโอกาส (Weight / เปอร์เซ็นต์)

- ระบบใช้ **น้ำหนักสัมพัทธ์** ไม่ใช่ % ตายตัว
- โอกาสช่อง A = `weight ของ A ÷ ผลรวม weight ของช่องที่ active และยังมี stock`
- Admin อาจใส่เป็น % (รวม 100) ก็ได้ — ระบบแปลงเป็น weight ให้
- ถ้า weight รวมไม่เท่า 100 ระบบ **ไม่ error** แต่อาจมีข้อความแจ้ง admin

**ตัวอย่าง:**

| ช่อง | weight | โอกาสเมื่อทุกช่อง active |
|---|---|---|
| 10 แต้ม | 40 | 40% |
| 50 แต้ม | 10 | 10% |
| คูปองเครื่องดื่ม | 5 | 5% |
| ลองใหม่ | 45 | 45% |

### 4.2 Stock (รางวัลจำกัดจำนวน)

ใช้เมื่อรางวัลมีจำนวนจำกัด เช่น iPhone 10 รางวัล

- ตั้ง `stock_total = 10` → ชนะได้สูงสุด 10 ครั้งทั้งแคมเปญ (ช่องนั้น)
- พอ stock หมด ช่องนี้ **หายจากการสุ่ม** โอกาสช่องอื่นจะถูกคำนวณใหม่
- **สมาชิกไม่เห็น** stock เหลือ — เห็นเฉพาะ admin
- Admin แก้ `stock_remaining` กลางแคมเปญได้ (เติม stock)

> Stock ของ segment ≠ limit การหมุน และ ≠ limit การแลก reward ของ outcome ประเภท reward

### 4.3 ช่อง "ไม่ได้รางวัล" (No-Win)

- ตั้ง `is_no_win = true` และ **ไม่ใส่ outcome**
- ยังถูกสุ่มตาม weight ได้ — ใช้ทำช่อง "โชคดีครั้งหน้า"
- ยังนับเป็น 1 spin ต่อ limit
- ถ้ารางวัลทุกช่องหมด stock แต่มีช่อง no-win อยู่ → ระบบจะให้หมุนไปช่อง no-win ได้ (ไม่ error)

## 5. การตั้งค่ารางวัลจริง (Outcome)

เมื่อสมาชิกชนะช่องหนึ่ง ระบบมอบ **ทุก outcome** ในช่องนั้น

| outcome_type | entity_id | amount | ได้อะไร |
|---|---|---|---|
| **points** | ไม่ต้องใส่ | จำนวนแต้ม (> 0) | เติมแต้มเข้า wallet |
| **tickets** | ticket_type_id | จำนวนตั๋ว (> 0) | เติม ticket |
| **reward** | reward_id | จำนวน (มักเป็น 1) | push reward ให้สมาชิก (เหมือนแลก reward) |
| **earn_factor** | earn_factor_id | ไม่บังคับ | ตัวคูณแต้มช่วงเวลา (metadata: `window_days`, default 30 วัน) |

**หนึ่งช่อง หลายรางวัล:** ช่องเดียวตั้ง outcome ได้หลายแถว — เช่น 10 แต้ม + 1 ticket + 1 reward พร้อมกัน

**ข้อควรบอกลูกค้า:** reward outcome ยังต้องผ่านเงื่อนไข/limit ของ reward นั้น ณ เวลามอบ — ถ้า reward หมดหรือ dispatch ล้มเหลว **ทั้งครั้งหมุนจะ rollback** (ไม่หักเงิน)

## 6. การตั้งค่าการแสดงผล (display_config)

แยกเป็น 2 ระดับ — **ไม่กระทบ logic การสุ่ม** ระบบ backend เก็บ JSON ตามที่ admin ส่ง ไม่ validate key

### 6.1 ระดับแคมเปญ (`spin_wheel.display_config`)

ใช้ตกแต่งหน้าวงล้อ เช่น:

| กลุ่ม (ตัวอย่าง) | key ตัวอย่าง | ใช้ทำอะไร |
|---|---|---|
| banner | hero_image, title, subtitle | แบนเนอร์ด้านบน |
| wheel | center_image, pointer_color | รูปกลางวงล้อ, สีลูกศร |
| theme | primary_color, background_gradient | ธีมสีหน้า |
| labels | spin_button, win_modal_title | ข้อความปุ่ม/ modal |

### 6.2 ระดับช่อง (`spin_wheel_segment.display_config`)

| key ตัวอย่าง | ใช้ทำอะไร |
|---|---|
| color | สีช่องบนวงล้อ |
| icon_url / icon | ไอคอนช่อง |
| subtitle | ข้อความรอง |
| badge | ป้าย เช่น "JACKPOT" |

**สิ่งที่ไม่ควรใส่ใน display_config:** ชื่อแคมเปญ, label ช่อง, weight, stock, รายการ outcome — ฟิลด์เหล่านี้มี column แยกอยู่แล้ว

**i18n:** ระบบไม่แปลภาษาให้อัตโนมัติ — ถ้าต้องการหลายภาษา ให้ admin ใส่ข้อความใน JSON หรือให้แอปจัดการเอง

## 7. สิ่งที่สมาชิกเห็น vs Admin เห็น

| ข้อมูล | สมาชิก | Admin |
|---|---|---|
| ชื่อ, คำอธิบาย, display_config | ✓ | ✓ |
| โอกาส (weight_pct) | ✓ (ถ้าแอปโชว์) | ✓ (weight + %) |
| รายการ outcome / รางวัลจริง | ✗ (ก่อนหมุน) | ✓ |
| stock เหลือ | ✗ | ✓ |
| spins_remaining, can_spin | ✓ | — |
| ยอด balance | ✓ | — |

**can_spin = true** เมื่อครบทุกข้อ: แคมเปญ active + อยู่ในช่วงเวลา + ผ่าน eligibility + ยังไม่เกิน limit + balance พอ (ถ้ามีค่าใช้จ่าย)

## 8. กฎสำคัญที่ CS ควรรู้

1. **หมุนหนึ่งครั้ง = ช่องเดียว** — ไม่มีการชนะหลายช่องในครั้งเดียว
2. **หักเงินและมอบรางวัลในธุรกรรมเดียว** — ล้มเหลวตรงไหน rollback ทั้งหมด
3. **ไม่หักเงินถ้าไม่มีช่องที่ชนะได้เลย** (ไม่มี active segment และไม่มี no-win fallback)
4. **Limit นับทุกครั้งที่หมุน** รวมช่อง no-win
5. **ลบแคมเปญ:** ถ้ามีประวัติ spin แล้ว → soft delete (ปิด active เท่านั้น); ถ้ายังไม่มีใครหมุน → ลบถาวร
6. **ชื่อช่อง ≠ รางวัลจริง** — ตรวจ outcome เสมอเมื่อลูกค้าถามว่า "ชนะแล้วได้อะไร"

## 9. FAQ / Troubleshooting สำหรับ CS

### "สมาชิกกดหมุนไม่ได้ (can_spin = false)"

เช็คตามลำดับ:

1. แคมเปญ **active** และอยู่ใน **window_start – window_end** หรือไม่
2. สมาชิก **ผ่าน eligibility** หรือไม่ (tier / persona / tag / เดือนเกิด)
3. **spins_remaining = 0** หรือไม่ (เกิน limit)
4. **balance ไม่พอ** สำหรับ cost หรือไม่

### ข้อความ error ที่พบบ่อย

| ข้อความ | สาเหตุ | แนะนำลูกค้า/สมาชิก |
|---|---|---|
| Tier / Persona / Tag / Birthday month requirement not met | ไม่ผ่านเงื่อนไขสิทธิ์ | ตรวจ tier/persona/tag/วันเกิดของสมาชิก |
| Personal participation limit reached | เกิน limit รายบุคคล | รอ reset ตาม time_unit หรือปรับ limit |
| Campaign participation limit reached | แคมเปญครบ quota รวม | ปิดแคมเปญหรือเพิ่ม total limit |
| insufficient_balance | แต้ม/ตั๋วไม่พอ | เติม balance หรือลด cost |
| no_prize_available | ไม่มีช่องที่สุ่มได้ และไม่มี no-win | เพิ่ม stock / เปิด segment / เพิ่มช่อง no-win |
| Spin wheel campaign not found or inactive | id ผิด, ปิดแคมเปญ, หรือหมดช่วงเวลา | ตรวจ active และ window |

### "สมาชิกบอกหมุนแล้วไม่ได้แต้ม"

1. ชนะช่อง **is_no_win** หรือไม่
2. ดู outcome ของช่องนั้น — อาจเป็น ticket/reward ไม่ใช่ points
3. ถ้า dispatch ล้มเหลว ระบบ rollback — สมาชิก **ไม่ถูกหัก** และไม่ได้รางวัล
4. ใช้ spin log / outcome_distribution_log ตรวจ (ทีม ops/support)

### "โอกาสชนะไม่ตรงที่ตั้ง"

- ช่องที่ **stock = 0** หรือ **inactive** จะไม่ถูกนับ — % ที่เหลือถูกคำนวณใหม่
- weight เป็น **สัมพัทธ์** ไม่ใช่ % คงที่ถ้ามีช่อง drop ออก

## 10. ตัวอย่างการตั้งค่าที่ใช้บ่อย

### ตัวอย่าง A — วงล้อแต้ม หมุน 50 แต้ม/ครั้ง 3 ครั้ง/วัน

- cost: points × 50
- limit: user, 3, day
- ช่อง: 10 แต้ม (40), 50 แต้ม (10), คูปอง (5), ลองใหม่ no-win (45)

### ตัวอย่าง B — หมุนด้วย Spin Token ชนะ token กลับ

- cost: ticket × 1 (Spin Token)
- outcome ช่องหนึ่ง: tickets × 2 (Spin Token เดียวกัน)

### ตัวอย่าง C — รางวัลใหญ่จำกัด 10 รางวัล

- segment "iPhone Voucher": weight 1, stock_total 10
- outcome: reward × 1

## 11. ฟีเจอร์ที่เกี่ยวข้อง

| ฟีเจอร์ | ความสัมพันธ์ |
|---|---|
| **Currency / Wallet** | หักแต้ม, เติมแต้มจาก outcome points |
| **Ticket** | ใช้เป็นค่าหมุนหรือรางวัล |
| **Reward** | outcome ประเภท reward ใช้ flow แลก/มอบ reward |
| **Tier / Persona / Tag** | ใช้ใน eligibility เหมือน reward และ check-in |
| **Transaction limits** | ใช้ตารางเดียวกับ reward/check-in สำหรับ cap การหมุน |
